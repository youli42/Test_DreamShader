PixelOutline：改了什么、怎么学、关键点在哪

把 Unity URP 的 ScreenPixel 像素描边 Renderer Feature，移植成 UE 5.8 的一个渲染插件。 核心是三个全屏 Pass：全分辨率检测边缘 → 按像素块 max 归约 → 按块索引合成描边。

03效果与三段式管线

最终画面 = 像素块化的场景颜色 + 严格对齐像素块的整块描边。两个难点：

  • 细轮廓不能因为没有经过块中心而丢失 → 所以检测必须在全分辨率做。
  • 描边要占完整像素块，不能一块里只有零散几个点 → 所以归约必须用 max。
输入

Tonemap 之后的 SceneColor（全分辨率）

Bloom/Vignette/Tonemap 已生效
▼
Pass0 · PixelAndDetect · PS · 全分辨率
Pass 0

像素化 + 四路 Sobel + 二值化

→ PackedColorAndEdge, PF_A16B16G16R16
  • 线性采样做像素化，fwidth 平滑块边界（不是硬 floor）
  • 3×3 Sobel，一个 unroll 循环同时累积四路信号：深度 / 世界法线 / 亮度 / RGB
  • smoothstep(t, t+softness) → step(0.5) 二值化
  • 输出：RGB = 像素化颜色，A = 二值边缘掩码
▼
Pass1 · ReduceOutline · PS · 画到低分辨率网格（1 像素 = 1 块）
Pass 1

块内 max 归约

→ OutlineGrid, ceil(W/bs) × ceil(H/bs)
  • A 通道取块内 max（不是平均、不是中心采样），命中 1.0 即 break
  • RGB 取块中心颜色（与描边共用同一套块网格）
▼
Pass2 · Composite · PS · 全分辨率
Pass 2

按块索引合成

→ 写回 OverrideOutput 或 SceneColor
  • 屏幕 UV 反算块索引 → 网格 UV = (blockIndex + 0.5) / gridSize，Point 采样
  • lerp(块颜色, 描边色, step(0.5, mask) * alpha)
  • 输出 Alpha 必须是 0（UE 语义：0 = 不透明，与 Unity 相反）

插入点怎么选的

UnityUE
RenderPassEvent 600 / AfterRenderingPostProcessingEPostProcessingPass::Tonemap = BL_SceneColorAfterTonemapping

语义一致：Bloom、Vignette、Tonemapping 的结果都会一起进像素块网格。 实现上三个 Pass 在同一个回调里顺序添加，天然满足 Pass1/2 不早于 Pass0 的依赖（等价于 Unity 里 outlinePassEvent 被钳制到不早于 pixelPassEvent）。

04关键点 1：顺序不能反（这是整个移植的灵魂）

为什么必须「全分辨率检测 → 块归约 → 合成」，而不是更简单的两种做法？下面这个实验可以直接看出来。 它用一张合成场景（大圆 + 一条亚像素级细线），对比三种策略：

① 全分辨率边缘掩码检测在原始分辨率上做，细线完整保留
基准真值
② A：先降采样，再检测块中心采样深度 → 细线几乎从不落在块中心
✗ 细轮廓直接消失
③ B：全分辨率检测，但块中心采样掩码只取块中心一个点
✗ 描边断断续续、块内不均
④ C：全分辨率检测 + 块内 max（本实现）块内任一像素命中 → 整块描边
✓ 细线保住，且整块均匀

演示为简化模型：只取深度一路信号、用中心差分近似 Sobel、step 代替 smoothstep+step；结论与真实管线一致。 注意看「描边块占比」：A 明显低于 C，差值就是被降采样吃掉的细轮廓。

源码对照

// Pass1 ReduceOutline —— 块内 max，命中即退出
[loop] for (int y = 0; y < 64; y++)
{
    if (y >= BlockSize.y || BlockStart.y + y >= SourceSize.y) break;
    [loop] for (int x = 0; x < 64; x++)
    {
        if (x >= BlockSize.x || BlockStart.x + x >= SourceSize.x) break;
        BlockMask = max(BlockMask, SamplePackedAlpha(BlockStart + int2(x, y), SourceSize));
        if (BlockMask >= 1.0) break;      // 已经确定是描边块
    }
    if (BlockMask >= 1.0) break;
}

05关键点 2~5

关键点 2：一切合并都用 max，不用求和 / 平均

四路信号（深度 / 法线 / 亮度 / RGB）合并也是 max：

float GeometryEdge   = max(SobelEdges.x * Weights.x, SobelEdges.y * Weights.y);   // 深度 / 法线
float LuminanceEdge  = SobelEdges.z * Weights.z * step(0.5, UseLuminanceEdge);
float AppearanceEdge = max(LuminanceEdge, SobelEdges.w * Weights.w);             // 亮度 / 颜色
return max(GeometryEdge, AppearanceEdge);
为什么：避免「多个低强度噪声相加被误判成真实边缘」。求和会让噪声累积越过阈值， max 则要求某一路信号自身足够强才算边缘。这是 Unity 原实现的选择，必须复刻。

关键点 3：三个 Pass 的块索引必须完全一致

三个 Pass 共用同一套源像素尺寸（对应 Unity 的 _ScreenPixelSourceSize，由 Feature 显式传入而非读相机尺寸）：

  • SourceSizeAndInvSize = (W, H, 1/W, 1/H) —— 全分辨率
  • GridSizeAndBlockSize.xy = ceil(W/bs) × ceil(H/bs)，.zw = 块尺寸（clamp 到 [1,64]）
// 块索引（与 Unity 逐字一致）
blockIndex  = min(floor(saturate(UV) * sourceSize / blockSize), gridSize - 1);

// 块中心 UV —— 处理最后一行/列不足整块的情况
blockStart  = blockIndex * blockSize;
blockExtent = min(blockSize, sourceSize - blockStart);
blockCenter = (blockStart + 0.5 * blockExtent) / sourceSize;
这里踩过最贵的坑：参数块里混用 FIntPoint(int2) 与 FVector4f 时， CPU 打包与 HLSL cbuffer 对齐规则不一致，GridSize/BlockSize2D 在着色器里读到 0 → 每个块颜色都取自左上角那一个像素 → 整屏一个颜色。 而 A 通道（掩码）不依赖这两个值，所以症状是「有边缘信号但画面纯色」，极易误判。

修复：公共参数块全部改成 FVector4f（GridSize 与 BlockSize2D 合并成 GridSizeAndBlockSize 的 xy / zw），让 CPU 与 HLSL 按 16 字节对齐天然一致。

关键点 4：先二值化，再归约（顺序不能反）

softMask = smoothstep(Threshold, Threshold + Softness, response);
mask     = step(0.5, softMask);        // 硬二值
// 然后才是 Pass1 的块内 max 归约

先软后硬，保证归约阶段只看到「整块描边 / 整块干净」，不会出现渐变黑边。 如果把浮点响应直接拿去 max，一个块内只要有一点点响应就会被放大成整块描边。

关键点 5：合成必须 Point 采样 + 块中心 UV

int2  BlockIndex = GetPixelBlockIndex(UV, SourceSize, GridSize, BlockSize);
float2 GridUV    = ((float2)BlockIndex + 0.5) / (float2)GridSize;   // 命中网格 texel 中心
float4 GridSample = GridTexture.SampleLevel(GridPointSampler, GridUV, 0);

这样同一块内每个屏幕像素读到完全相同的 texel，描边天生块对齐。换成 Bilinear 就会出现块与块之间的颜色渗透。

Sobel 细节

kSobelX = {-1, 0, 1, -2, 0, 2, -1, 0, 1}      // 中心权重 0
kSobelY = { 1, 2, 1,  0, 0, 0, -1,-2,-1}
kSobelNormalization = 0.25;                    // 两侧权重各和为 4，归一化到便于设阈值的范围
SampleStep = 1/SourceSize * Thickness;         // 步长以「源像素」为单位

一次 [unroll] for (i = 0..8) 内同时累积四路信号，避免四次重复采样偏移计算。

08学习路线（建议 3~4 个晚上）

阶段 0 · 跑起来，建立直觉（30 分钟）

目标：知道「对/错」长什么样
  • 打开 Content/PixelOutline/L_PixelOutline_Showcase，确认看到像素化 + 白色块状描边。
  • 控制台反复横跳 r.PixelOutline.Enable 0 / 1，确认开关彻底。
  • 拖 r.PixelOutline.PixelSize（1→64），感受块大小与描边粗细的关系。

验收：能一句话说出「描边是整块的，不是细线」。

阶段 1 · 用 DebugMode 拆开管线（1 小时）

目标：把黑盒拆成三段，定位问题不再靠猜
  1. r.PixelOutline.DebugMode 2 —— 全分辨率掩码。全黑 → 调小 EdgeThreshold 或调大 DepthWeight；全白 → 反之。
  2. r.PixelOutline.DebugMode 3 —— 块级掩码。确认与像素块对齐。
  3. r.PixelOutline.DebugMode 1 —— 像素化颜色。确认像素化正常。
  4. r.PixelOutline.DebugMode 0 —— 合成结果。

排查顺序固定为 2 → 3 → 0。这比任何日志都快。

阶段 2 · 读代码（2 小时）

目标：能在脑内跑通数据流
  • 按 §7 的顺序读一遍，边读边对照 §3 的管线图。
  • 重点盯三处：块索引计算、块内 max 循环、Pass2 的 Point 采样。
  • 拿张纸画出：一张 1920×1080、PixelSize=13 的画面，GridSize 是多少？最后一块的 extent 是多少？

阶段 3 · 动手改（2 小时）

目标：从「读过」变成「能改」
  1. 把描边改成红色 → 理解 OutlineColor 与 alpha 语义。
  2. 打开 RGB 信号：r.PixelOutline.ColorWeight 1，观察材质颜色边界被描出来 —— 理解第四路信号。
  3. 把 kSobelNormalization 改成 1.0，观察阈值需要如何跟着变 —— 理解归一化系数的意义。
  4. 把 Pass1 的 max 换成 sum / count（平均），亲眼看描边变淡变碎 —— 这一步最能建立直觉。
  5. 把 Pass2 的 Point 采样换成 Bilinear，看块边界渗色。

阶段 4 · 理解参数标定（1 小时）

目标：知道 Unity 的数值为什么不能直接抄

原因：UE 深度已线性化、法线未归一化、AfterTonemapping 处颜色值域不同。

  1. r.PixelOutline.NormalWeight 0（ColorWeight、UseLuminanceEdge 默认已是 0）→ 只留深度信号。
  2. DebugMode 2 下把深度信号调到稳定。
  3. 再加回法线：r.PixelOutline.NormalWeight 1，同样方式微调。
  4. DebugMode 3 → DebugMode 0 收尾，按需调 PixelSize。

本机参考量级：默认权重下掩码覆盖 2.5%；DepthWeight 20 时 28.9%。

阶段 5 · 进阶（可选）

  • 时域稳定：对边缘响应做轻量 TAA 式混合，根治移动时的描边闪烁。
  • 性能：Pass1 的双层循环最坏 64×64 次采样/块，可考虑改成 compute（但要先解决坑 3）。
  • 形态：把描边做成可配置的内描边/外描边、按物体 ID 分色。

10自测：我懂了吗

先自己答，再展开看答案。

Q1：为什么不能「先降采样到块分辨率，再做 Sobel」？
细轮廓（宽度 < 块尺寸）在降采样时就被丢掉了 —— 降采样只取块中心/平均，1~2 像素宽的线几乎不可能影响块中心的值。§4 的实验面板 ② 就是这个情况。
Q2：为什么块内归约用 max 而不是平均？
要让「块内只要有一个边缘像素，整块就是描边块」。平均会把一个强边缘稀释成 1/N²，导致描边块颜色深浅不一、甚至低于阈值消失。§5 关键点 2。
Q3：四路信号为什么用 max 合并，而不是加权求和？
防止多个低强度噪声相加被误判成真实边缘。max 要求某一路信号自身足够强。
Q4：二值化和归约，谁先谁后？为什么？
先二值化（smoothstep → step(0.5)），再归约。这样归约阶段只看到 0 或 1，输出必然是「整块描边 / 整块干净」，不会出现渐变黑边。
Q5：1920×1080、PixelSize=13，GridSize 是多少？最后一块的 extent 是多少？
GridSize = ceil(1920/13) × ceil(1080/13) = 148 × 84。 最后一块：blockStart.x = 147×13 = 1911，extent.x = min(13, 1920-1911) = 9（不足整块）。 blockStart.y = 83×13 = 1079，extent.y = min(13, 1080-1079) = 1。这正是 blockExtent = min(blockSize, sourceSize - blockStart) 存在的意义。
Q6：UE 后处理 Pass 输出的 Alpha 应该写 0 还是 1？
写 0。UE 后处理的 alpha 语义与 Unity 相反：0 = 不透明。Unity 原实现返回 1.0，直接照抄会出问题。
Q7：着色器里读 GBufferA 的正确写法是什么？
SceneTexturesStruct_GBufferATexture.SampleLevel(SceneTexturesStruct_PointClampSampler, UV, 0).rgb * 2.0 - 1.0，并且要自己 normalize()（UE 给的是未归一化的）。注意是下划线展平名，不是点号。
Q8：加了一个新的松散 shader 参数，编译通过了但值恒为 0，最可能的原因？
UE 不会为松散参数生成 HLSL 声明 —— 必须在 .ush 里自己写。参照引擎的 PostProcessDownsample.usf。

12已知问题与下一步

问题 1 · 移动视角时描边闪烁

已排除逐帧噪声/抖动（TAA 开/关的帧间差异都是 0.00%）。闪烁只在相机移动/缩放时出现，是两层叠加：

  1. 算法固有放大：Sobel → 二值化 → 块归约，会把亚像素级边缘抖动放大成「整块描边开/关」。
  2. 参数处在噪声带：默认 DepthWeight 1.5 下掩码仅覆盖 2.5%，阈值 0.08 卡在响应噪声带边缘。

缓解：DepthWeight 1.5 → 5（实验 20 时掩码升到 28.9%，远离噪声带）、EdgeSoftness 0.04 → 0.1+。 根治：对边缘响应做轻量时域混合。

问题 2 · 拉伸视口时出现异常外围显示

已排除输入/输出尺寸错位（实测 source=1096x520 outputTex=1096x520 完全一致）。

当前判断：视口拉伸的过渡帧中 ViewRect 扩大超出 RT 已渲染区域，Pass2 沿用 ENoAction， 未写入的外围区域显示上一帧残影或未初始化内容。

下一步：插件已加 PixelOutline extents: 日志（尺寸变化时输出）。复现时把该日志发来即可判定：

  • 拉伸中 source 与 outputTex 持续不一致 → 分辨率同步问题，改为中间纹理合成再 blit；
  • 仅瞬间不一致 → resize 瞬态，按「ViewRect ≠ RT 全区时改用 EClear」修复。
